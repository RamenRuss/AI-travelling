# Как добавить инструмент (погода, места, маршрут…)

Реестр `app/tools/registry.py` сам находит модули в `app/tools/`. Править агента, реестр или фронтенд не нужно.

## 5 шагов
1. Скопируйте `app/tools/_template.py` в `app/tools/weather.py` (имя без «_» в начале).
2. Реализуйте функцию. Первый аргумент всегда `ctx`, остальные — параметры из схемы:
   ```python
   def get_weather(ctx, city, days=3):
       data = ...                       # запрос во внешний API, не забудьте timeout
       if not data:
           return {"error": "Не удалось получить прогноз"}   # не бросайте исключения
       return {"city": city, "forecast": [...]}
   ```
3. Опишите схему в `TOOLS` (формат OpenAI tool calling). **`description` — это то, по чему модель выбирает тул**,
   пишите когда его вызывать.
4. Добавьте функцию в `TOOL_FUNCS = {"get_weather": get_weather}` и подпись шага в
   `STEP_LABELS = {"get_weather": "Запрашиваю прогноз погоды"}` (она видна пользователю в «Ход работы агента»).
5. Проверьте без модели:
   ```
   python -c "from app.tools import registry as r; print(sorted(r.TOOL_FUNCS)); print(r.run_tool('get_weather', {'city': 'Находка'}, r.new_context()))"
   ```
   Запросы к внешним API делайте через `from ._http import http_json` — там кэш, повторы при сбоях и таймауты.

Если что-то не так, при старте будет понятная ошибка: схема и функция не совпадают, нет `ctx`, имя тула занято.

## Карта
Хотите точку на карте — добавьте в контекст:
```python
ctx["markers"].append({"name": "Находка", "lat": 42.82, "lon": 132.87, "note": "Погода: +21°"})
```
Маркеры от разных инструментов для одного места склеиваются. Если маршрута нет, все маркеры попадут в ответ
агента как `map`. Для инструмента маршрута добавляйте его остановки в `ctx["route_markers"]`, а геометрию —
в `ctx["routes"]` (список): `{"coords": [[lon, lat], ...], "source": "OSRM"}`. Когда маршрут построен,
карта показывает только остановки из `route_markers` и линии маршрутов. Не пишите в результат инструмента API-ключи и внутренние адреса:
он уходит модели, а часть текста — пользователю.

## Правила хорошего инструмента
- Возвращает словарь, ошибки — `{"error": "..."}` с текстом, который модель сможет пересказать.
- Короткий ответ: модель читает всё, что вернули. Не отдавайте сотни строк, добавляйте `limit`.
- Говорите о неполноте данных в `note`, чтобы модель не додумывала.
- Секреты (ключи API) — в `.env` через `os.environ`, не в коде.

## Отключить инструмент
`DISABLED_TOOLS=find_fuel` в `.env`. Тул пропадёт у модели без правки кода.

## Заменить мок настоящим источником
Создайте модуль с теми же именами тулов (`find_fuel` …) и добавьте старые в `DISABLED_TOOLS`. Либо правьте
функции в `mock_data.py`, сохранив формат ответа (`docs/DATA.md`).
