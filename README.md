# Бухта — AI-ассистент для путешествий по Приморскому краю

FastAPI-приложение: фронтенд, регистрация/вход (SQLite), чат с агентом. Агент — языковая модель (через LLM-прокси),
которая сама вызывает инструменты: места, погода, маршруты, АЗС, жильё, транспорт. Помнит предыдущие сообщения чата.

## Запуск (Windows, cmd)

```
cd primorye-ai
python -m venv .venv
.venv\Scripts\activate.bat
pip install -r requirements.txt
set SPIRIT_API_KEY=ваш_ключ
copy .env.example .env
uvicorn app.main:app --port 5000
```

Открыть: http://127.0.0.1:5000. Linux/macOS: `source .venv/bin/activate` и `export SPIRIT_API_KEY=...`.
Ключ можно записать и в `.env` (скопируйте `.env.example`), но **переменная окружения важнее файла**.
Нужен Python 3.9+. Проверка ключа и модели: `python scripts/check_llm.py`.

> Если раньше в вашем `.env` стояло `AGENT_MODE=mock`, замените на `AGENT_MODE=real` или удалите строку — иначе чат будет отвечать заготовками.

Тесты (без интернета и ключей): `pip install -r requirements-dev.txt` и `python -m pytest -q`

## Что умеет агент

| Инструмент | Что делает | Источник |
| --- | --- | --- |
| `search_places` | найти конкретное место по названию | Google Places (если есть ключ) или OpenStreetMap |
| `find_places` | подборка мест рядом с городом: музеи, пляжи, смотровые, природа, кафе… | OpenStreetMap (Overpass) |

**Уточняющие вопросы.** Если для плана или маршрута не хватает сроков, способа передвижения или города старта, агент не
составляет план, а одним сообщением задаёт недостающие вопросы (заголовок «Нужно уточнить»). Правила — блок «УТОЧНЕНИЯ»
в `llm.py`; служебная метка `[УТОЧНЕНИЕ]` в ответе модели снимается в `split_clarify`. Переспрашивать второй раз агент не будет:
по хвосту прошлого вопроса (`CLARIFY_TAIL`) `already_clarified` добавляет в промпт указание составлять план с допущениями.
На простые вопросы (погода, цена, расписание) агент отвечает сразу. Проверка на живой модели — запросы 11–14 в `eval/queries.csv`.

Изменить значения по умолчанию — `DEFAULT_BEACH_LIMIT` / `MAX_BEACH_LIMIT` в `_ctx.py`.
| `get_weather` | погода сейчас и прогноз до 7 дней | Open-Meteo |
| `get_route` | расстояние и время между двумя координатами по дорогам | OpenRouteService (ключ, если задан) → routing.openstreetmap.de (авто/вело/пешком) → router.project-osrm.org (авто) |
| `route_by_places` | маршрут по дорогам через места плана (по id), один вызов на весь маршрут: км и минуты по каждому перегону и итого | то же (`app/tools/_roads.py`) |
| `find_fuel`, `find_lodging`, `find_transport` | АЗС, жильё, расписания | **демо-данные** `app/data/mock/*.csv` |

Первые четыре — настоящие внешние API; последние — демонстрационные CSV (обновляются через `scripts/xlsx_to_csv.py`),
в системном промпте модели прописано, что на них нельзя полагаться как на точные. На карте — только точки итогового плана: каждому найденному месту инструменты дают id (p1, p2…), модель в конце плана пишет
строкой `ROUTE: p3 p1 | p5 p2` (| — граница дней), сервер подставляет координаты по id и убирает строку из текста. Если модель не вывела эту строку, выбранные ею id из вызовов `route_by_places` становятся резервным источником точек карты. **Дороги строятся во время составления плана**: как только модель выбрала места, она вызывает `route_by_places` один раз на весь маршрут (все дни, от старта до финиша), и сервер сразу строит настоящие дороги по каждому перегону и запоминает их в контексте запроса (`ctx["legs"]`). К моменту, когда модель пишет ответ, геометрия уже готова, а кнопка «Показать на карте» только показывает её: `_ctx.build_map_payload` берёт готовые участки и достраивает только недостающие (например, переезд между днями или участок, который не вышел с первого раза; при сбое сервиса маршрутов `_roads.route_leg` делает вторую попытку). Если дороги нет (остров без моста) или сервис
не ответил, участок на карте идёт серым пунктиром с пометкой, а не выдаётся за дорогу. Так координаты не выдумываются, а альтернативные места на карту не попадают.

Дорога рисуется между **всеми** соседними точками плана, в том числе между днями, — получается сплошной путь от старта до финиша. Время в пути на карте не показывается.

## Скорость и расход токенов

- Инструменты одного шага модели выполняются **параллельно**; в промпте — «все нужные вызовы одним шагом» (меньше кругов запрос↔модель, а каждый круг заново оплачивает весь контекст).
- Overpass: несколько зеркал опрашиваются одновременно (`OVERPASS_URLS` — свой список), упавшее зеркало 90 с не трогаем, результаты кэшируются на диске (`app/.cache/`, неделя; папку можно менять через `BUKHTA_CACHE`), запасной вариант — Nominatim. Если всё недоступно, модель получает указание не повторять вызов.
- Ответы инструментов компактные (без адресов-«простыней», ссылок, лишних полей погоды); потолок ответа модели — `MAX_OUTPUT_TOKENS` (по умолчанию 6000).

## Режимы агента

| `AGENT_MODE` | Что отвечает | Что нужно |
| --- | --- | --- |
| `real` (по умолчанию) | `app/agent/llm.py` — модель + инструменты из `app/tools/registry.py` | `SPIRIT_API_KEY` |
| `mock` | `app/agent/mock_agent.py` — регулярки и готовые планы (для тестов) | ничего |
| `custom` | ваш агент: `AGENT=пакет.модуль:функция` | см. `docs/ADD_AGENT.md` |

Как подключить агента — `docs/ADD_AGENT.md`, как добавить инструмент — `docs/ADD_TOOL.md`, формат данных — `docs/DATA.md`.

## Безопасность

**База данных (`app/db.py`)**
- Все SQL-запросы параметризованы — SQL-инъекции через формы и API невозможны.
- Пароли: PBKDF2-HMAC-SHA256, 600 000 итераций, соль на каждого пользователя. Старые хэши (200 000) обновляются автоматически при следующем входе.
- Токены сессий в БД хранятся только в виде SHA-256: если файл БД утечёт, по нему нельзя войти в чужой аккаунт.
- Соединения всегда закрываются, включены WAL и `busy_timeout`; файл БД получает права 600 (на Windows не действует).
- Состояние чатов пользователя ограничено ~1 МБ.
- Старая БД мигрирует сама (колонки `surname`, `iters`); при первом запуске новой версии все старые сессии сбрасываются — нужно войти заново.

**Сервер (`app/main.py`, `app/security.py`)**
- Проверка входных данных: имя и фамилия — только буквы, длины ограничены, пароль 8–128 символов, сообщение до 1500 символов.
- Защита от перебора: 6 неудачных входов на пару IP+email за 15 минут → блокировка (лимит проверяется до хэширования). Регистрации — 10 в час с одного IP.
- Время ответа при входе одинаковое для существующего и несуществующего email.
- Лимиты чата на пользователя: 10 запросов в минуту, 300 в сутки, один запрос к модели одновременно (`CHAT_PER_MINUTE`, `CHAT_PER_DAY`).
- Защита от CSRF (проверка `Origin`) + `SameSite=Lax`; cookie `HttpOnly`, при HTTPS — `Secure` (`COOKIE_SECURE=1`).
- Заголовки: CSP, `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy`, HSTS (при HTTPS). `/docs` и `/openapi.json` выключены (включаются `DEBUG=1`).
- История диалога принимается только с ролями user/assistant, роль system с клиента отбрасывается; в промпте — защита от «забудь инструкции» и от команд внутри данных инструментов.
- Внутренние ошибки модели и сервера пользователю не показываются, подробности пишутся только в лог.
- Ответы модели на странице экранируются перед выводом (XSS), разрешены только **жирный**, списки и https-ссылки.

**Что остаётся на вас**
- `.env` и `*.db` не кладите в git/архивы/облако (они в `.gitignore`). Ключ, попавший в чат, письмо или скриншот, считайте скомпрометированным и перевыпустите.
- Лимиты хранятся в памяти одного процесса: при нескольких воркерах (`--workers N`) вынесите их в Redis/nginx.
- При публикации в интернет: HTTPS (nginx/Caddy), `COOKIE_SECURE=1`, `TRUST_PROXY=1` (только за своим прокси).
- Библиотеки Leaflet подключаются с unpkg.com; для полной автономности скачайте их в `app/static` и уберите unpkg из CSP.
- Сброс пароля и подтверждение email не реализованы.

## Структура

```
primorye-ai/
├── app/
│   ├── main.py            # FastAPI: статика, auth, состояние чатов, /api/chat, /api/health, защита
│   ├── security.py        # лимиты запросов, заголовки (CSP…), проверка имён
│   ├── config.py          # ключи, режим, лимиты из окружения / .env
│   ├── db.py              # SQLite: users (имя, фамилия), sessions, user_state
│   ├── agent/
│   │   ├── __init__.py    # respond(): переключатель real / mock / custom
│   │   ├── llm.py         # цикл «модель ↔ инструменты», ретраи, промпт с текущей датой
│   │   ├── real_adapter.py# ответ llm.py (+ история) -> формат фронтенда
│   │   ├── contract.py    # формат ответа + finalize()
│   │   └── mock_agent.py  # МОК
│   ├── tools/
│   │   ├── registry.py    # единый реестр: сам находит модули с тулами
│   │   ├── real.py        # search_places, get_weather, get_route
│   │   ├── osm_places.py  # find_places (OpenStreetMap)
│   │   ├── mock_data.py   # find_fuel, find_lodging, find_transport (демо-CSV)
│   │   ├── _http.py       # HTTP с кэшем и повторами (реестр пропускает файлы с «_»)
│   │   └── _template.py   # шаблон нового инструмента
│   ├── data/mock/         # демо-CSV
│   └── static/            # фронтенд + favicon (svg, ico, png)
├── eval/  scripts/  docs/  tests/
└── .env.example  .gitignore  requirements*.txt
```

## Эвал

```
python -m eval.run_eval --queries eval/queries.csv --label v1
python -m eval.run_eval --queries eval/queries.csv --label v2 --model <другая модель>
```

Результат — `eval/results_<label>.csv` (ответ, вызванные тулы, токены, цена, время). Оценку качества ставят вручную.

**Нет дорог на карте?** Запустите `python scripts/check_routing.py`: скрипт проверяет, достаёт ли ваш компьютер до сервисов маршрутов (OSRM, OpenRouteService), и показывает ошибку каждого.
